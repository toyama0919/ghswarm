# Skip repos with missing local path in loop / status

## Background / Purpose

When multiple repos are configured in `~/.ghswarm.yaml` and `ghswarm loop` (daemon polling) runs, if any repo's
local `path` does not exist yet (e.g. `repo: ai-journey-dena/ai-workspace`, `path: ~/github_dena/ai-workspace`
not yet cloned), the following currently happens every polling cycle:

- `run_process_cycle_worker` → `Orchestrator.__init__` ([orchestrator.py:48](../src/ghswarm/orchestrator.py#L48))
  calls `detect_default_branch(self.repo_root, ...)` when `cfg.base_branch` is unset. This runs `gh repo view`
  with the missing directory as cwd and fails (for repos with `base_branch` explicitly set, this call is
  skipped and the actual failure happens a bit later, during git operations).
- That exception is swallowed by `run_process_cycle_worker`'s `except Exception`
  ([cli.py:393](../src/ghswarm/cli.py#L393)) and only logged, so the daemon itself doesn't die, but the same
  error log repeats forever every `poll_interval`.

We want to check path existence once at `ghswarm loop` startup and exclude repos with a missing path from that
run's polling targets. Similarly, `ghswarm status` (when listing all repos) should exclude repos with a missing
path from the listing.

## Requirements

- At `ghswarm loop` startup (whether daemonized or not, before entering the polling loop), check once whether
  each targeted repo's `path` (after `~` expansion) exists as a local directory.
- For any repo whose path doesn't exist, log a warning once and exclude it from that process's polling targets
  (the list passed to `_run_parallel_cycle`, the `poll_interval` calculation, the `activity_dir` clearing
  target, etc.). Other repos continue to be processed as before.
- Apply this check to the list `cmd_loop` ultimately assembles as polling targets, including when repos were
  selected via explicit `-r` (if everything gets excluded down to zero, let it naturally fall into the existing
  "No target repositories" warning path).
- This check happens exactly once at process startup — not re-checked while the polling loop is running (a
  path created later is not picked up until the daemon is restarted).
- `ghswarm status` (when `-r` is omitted, i.e. listing all repos) similarly excludes repos with a missing path
  from the listing and logs a warning once. When a repo is explicitly targeted via `status -r <alias>`, it is
  not affected and keeps today's behavior (it still attempts to display).

## Non-goals

- `ghswarm run` and `ghswarm status -r <alias>` (explicit repo targeting) repo-selection logic (`_select_repos`'s
  result used as-is, `_select_single_repo_by_cwd`) is unchanged. Explicitly targeting a repo with a missing path
  there keeps today's behavior (it still attempts to process).
- No validation of whether the path is actually a git repository (e.g. `.git` presence) — only directory
  existence is checked.
- No dynamic re-detection of a path appearing/disappearing while the daemon/status command is running (a
  one-time check per invocation).

## Design approach

- Add a shared filter helper in `cli.py` (e.g. `_filter_missing_paths(repos: list[RepoConfig]) ->
  list[RepoConfig]`). For each `cfg`, check `Path(cfg.path).expanduser().is_dir()`; if missing,
  `log.warning(...)` and exclude it from the result; otherwise keep it. Preserve order.
- In `cmd_loop` ([cli.py:576](../src/ghswarm/cli.py#L576)), call this filter right after
  `repos = _select_repos(...)`, before the `if not repos:` check (applies regardless of explicit `-r`).
  Downstream `interval = min(r.poll_interval for r in repos)` and `_run_parallel_cycle(repos, ...)` then operate
  on the filtered list.
- In `cmd_status` ([cli.py:698](../src/ghswarm/cli.py#L698)), apply the same helper right after
  `repos = _select_repos(...)` only when `getattr(args, "repos", None)` is empty (i.e. `-r` omitted, listing
  all repos). When `-r` is explicit, skip the filter and call `_print_repo_status` as before.
- `_select_repos` itself (also used by `run`) is unchanged. The filter is applied only at the `cmd_loop` /
  `cmd_status` call sites.
- Log once per entry via `log.warning`, including the repo's alias, repo name, and resolved path (e.g.
  `"Repo '%s' (%s): path '%s' does not exist; skipping"`).
- No changes to `Orchestrator` (`detect_default_branch`) itself — this is prevented entirely by the caller-side
  pre-filter.
